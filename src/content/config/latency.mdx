TCPing 是节点自己发起的探测：每个节点按任务间隔向目标地址建立一次 TCP 连接，上报握手耗时。
连不上记 `-1`，也就是一次丢包。探测不经过 hub，所以能看到每条线路真实的到达质量。

## 创建探测任务

后台左侧的**延迟**页。任务有四个字段：

| 字段 | 说明 |
|---|---|
| 名称 | 卡片和图例上显示的标签，如「电信 163」 |
| 目标 | `host:port`，域名或 IP |
| 间隔 | 探测周期秒数，5–3600 |
| 节点 | 哪些节点执行这个任务，可多选 |

同一节点最多分配 64 个任务。任务的增删改立刻下发到在线节点，探测结果同时写入历史，
与指标历史按同一个保留天数清理。

## 状态页卡片

每张节点卡片的 TCPing 区按行列出每个任务：最近 20 次探测的圆点、最新耗时、这一窗口的丢包率。

圆点按耗时分色：低于 100 ms 绿，100–199 ms 黄，达到 200 ms 或丢包为红。行尾显示最新耗时
（超时显示「超时」）和窗口丢包率，悬停丢包率可见「最近 N 次探测丢包 M 次」；没有丢包的行
不显示丢包率。点这一区域直接进入该节点的延迟图表。

## 延迟图表

节点详情页的「网络延迟」页签：

- 每个探测分配固定颜色。上方统计卡片给出窗口**平均延迟、丢包率、平均波动**（相邻两次
  耗时的平均差值），丢包率标红。点卡片显隐对应曲线，右上角「全选 / 全不选」批量切换
- **部分丢包**的时段在曲线上画红色圆环；**全部丢包**的时段在图表底部画红色圆点，
  多个探测错位排列，一眼看出故障时段
- 悬停显示当桶每个探测的耗时与丢包率；整桶丢失的探测直接标「全部丢失」
- 单条曲线时叠加抖动范围带（Smokeping 的「烟雾」）
- **平滑峰值**开关用 Hampel 滤波削掉离群尖峰，丢包标记不受影响
- 窗口有 1 / 6 / 24 小时三档，底部拖柄可以缩放区间

窗口丢包率由 hub 在读取原始探测时按样本数计算，不是各时间桶百分比的平均——所以稀疏时段
的 50% 不会被误当成整体丢包率。
